# Using the skills with smaller or self-hosted models

The skills work with any client that can call Loomi Connect's tools, including ones that run open models you host yourself, for example through Ollama or LiteLLM. One thing works differently: the size of the tool list.

## The tool list is large

Most clients send the model the definition of every tool the MCP server lists (name, description and arguments) with every request. For Loomi Connect that's 111 tools, about **61,000 tokens**, before your question or any data.

Frontier models from Claude and OpenAI cache the tool list, so it costs little. A model on your own hardware has to read it at the start of each conversation, and again whenever the cache is cleared, for example when another conversation runs on the same model. On a laptop that can take minutes. It also uses up a context window that the skills and Loomi's answers need.

## Offer one area's tools

Every published tool belongs to an area: Engagement, Discovery or Data Hub. [`tool-areas.json`](tool-areas.json) lists them, together with the areas each skill uses:

```json
{
  "always": ["call_tool", "get_guide", "list_all_tools", "search_tools"],
  "areas": {
    "engagement": ["calculate_report", "..."],
    "discovery": ["get_discovery_query_performance", "..."],
    "datahub": ["search_datahub_jobs", "..."]
  },
  "skills": {
    "discovery-zero-results-triage": ["discovery"],
    "weekly-ecommerce-briefing": ["engagement", "discovery"]
  }
}
```

To keep the list short:

1. **Always offer** the `always` tools. `search_tools` finds any tool and `call_tool` runs it, so nothing is out of reach.
2. **Add the areas in play**:
   - for a skill, its entry under `skills`;
   - otherwise, the product the person is working in.

   A playbook's entry covers the skills its stages run.
3. **Filter the server's tool list** to those names. Your client gets the tool definitions from the server, as usual.

What each area costs, measured on the listed tools on 6 November 2026 (about 3.5 characters a token):

| Tools offered | Tools | About |
|---|---:|---:|
| All of them | 111 | 61,000 tokens |
| Discovery | 50 | 32,000 tokens |
| Engagement | 54 | 26,000 tokens |
| Data Hub | 3 | 2,000 tokens |

The area lists include tools the server reaches only through `call_tool`. Those have no definition to send, so a filtered list is never longer than the server's own.

## Keep approvals on `call_tool`

`call_tool` can run any tool, including ones that change live configuration. If your client asks a person before a write, apply the same check to the tool named inside `call_tool`'s arguments, not just to `call_tool` itself.

## Keeping it current

`tool-areas.json` is generated by `scripts/build_skill_index.py` from [`published-tools.txt`](published-tools.txt) and the skills. A tool's area comes from Loomi Connect's own tags, and a skill's areas come from the tools it names. Regenerate the file with that script whenever either changes. CI fails when it is out of date.
